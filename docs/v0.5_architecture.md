# GhostLM v0.5 — Architecture upgrades

Status: **planned**. Gated on the v0.4.2 corpus expansion (~50M tokens) so the
retrain has enough data to make use of the larger effective capacity.

This document specifies the four switches we plan to flip at the v0.5 retrain
and the rationale for each. All four are individually opt-in via config flags
so backward compatibility with Phase 1–4 checkpoints is preserved.

---

## What ships

| Switch | v0.4 (current) | v0.5 (planned) | Reason |
|---|---|---|---|
| Positional encoding | learned absolute | **RoPE** | free length-extrapolation; lower val-loss in every sub-1B comparison since 2023 |
| FFN activation | GELU | **SwiGLU** | +1–2 nat-loss across MobileLLM, Gemma, SmolLM2 reproductions |
| Normalization | LayerNorm | **RMSNorm** | half the params, ~5% faster, matches LayerNorm quality at this scale |
| Tokenizer | GPT-2 BPE (50K) | **Custom 32K** trained on cyber corpus | ~20% compression on technical text per BloombergGPT / Med42 / SciTokenizer measurements |

What we're **not** changing in v0.5:

- **GQA** — at 8 heads / 45M params the kv-cache cost is already trivial; defer to ghost-base 350M.
- **Mamba / SSM** — engineering cost on MPS-only is high; gain is marginal at 1024 ctx and 45M params.
- **Flash-Attention** — already a config flag; remains off on MPS (no kernel) and on for CUDA users.

## Config additions

Add to `ghostlm/config.py`:

```python
# v0.5 architecture flags — all default to current behavior so Phase 1–4
# checkpoints keep loading without modification.
use_rope: bool = False        # was already present
use_swiglu: bool = False      # new
use_rmsnorm: bool = False     # new
rope_base: float = 10000.0    # standard
```

`from_preset("ghost-small-v0.5")` flips all three flags True.

## Model changes

### `ghostlm/model.py`

Three small changes, each gated on its flag — old code path is preserved when
the flag is off.

**1. Position encoding (already partially wired):**

```python
if config.use_rope:
    self.rope = RotaryPositionalEmbedding(config.d_model // config.n_heads,
                                           config.context_length, config.rope_base)
else:
    self.position_embedding = nn.Embedding(config.context_length, config.d_model)
```

The existing `RotaryPositionalEmbedding` class at line 20 is already in the
file — just needs the wiring in `GhostLM.__init__` and per-block `attn.forward`.

**2. SwiGLU FFN.** Replace the current FeedForward block:

```python
class SwiGLU(nn.Module):
    """SwiGLU FFN — 2× memory of GELU for ~1.5× quality."""
    def __init__(self, config):
        super().__init__()
        # SwiGLU uses two parallel projections and gates one with SiLU.
        # We shrink hidden dim 2/3 to keep param count comparable.
        hidden = int(config.d_ff * 2 / 3)
        self.fc1 = nn.Linear(config.d_model, hidden, bias=False)
        self.fc2 = nn.Linear(config.d_model, hidden, bias=False)
        self.fc3 = nn.Linear(hidden, config.d_model, bias=False)
    def forward(self, x):
        return self.fc3(F.silu(self.fc1(x)) * self.fc2(x))


class FeedForward(nn.Module):  # current code, kept for use_swiglu=False
    ...
```

The block dispatches on `config.use_swiglu`.

**3. RMSNorm.** A drop-in replacement for `nn.LayerNorm`:

```python
class RMSNorm(nn.Module):
    """RMSNorm — LayerNorm without the mean subtraction or bias."""
    def __init__(self, dim, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(dim))
        self.eps = eps
    def forward(self, x):
        return self.weight * x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)


def make_norm(config, dim):
    return RMSNorm(dim) if config.use_rmsnorm else nn.LayerNorm(dim)
```

Each `Block.__init__` and the final `GhostLM.ln_f` use `make_norm(config, …)`.

## Tokenizer change

Train a 32K-vocab byte-pair tokenizer on the v0.4.2 corpus using the
HuggingFace `tokenizers` library:

```python
from tokenizers import Tokenizer
from tokenizers.models import BPE
from tokenizers.trainers import BpeTrainer
from tokenizers.pre_tokenizers import ByteLevel

tok = Tokenizer(BPE(unk_token="<|ghost_unk|>"))
tok.pre_tokenizer = ByteLevel()
trainer = BpeTrainer(
    vocab_size=32_000,
    special_tokens=[
        "<|ghost_bos|>", "<|ghost_eos|>", "<|ghost_pad|>", "<|ghost_unk|>",
        "<|ghost_user|>", "<|ghost_assistant|>", "<|ghost_end|>",
    ],
)
tok.train(["data/processed/train.jsonl"], trainer)
```

`GhostTokenizer` gets a `from_file` constructor switching tiktoken → tokenizers.
Both backends expose the same `encode_chat` / `decode` API; the model only
needs the integer ids.

Expected effect: ~20% fewer tokens per document on the v0.4.2 corpus. At fixed
training compute this is equivalent to ~25% more *effective* training data.

## Migration path

1. Land RoPE + SwiGLU + RMSNorm code (gated, default off — green CI on Phase 4).
2. Build the 50M-token v0.4.2 corpus.
3. Train the custom 32K tokenizer.
4. Pretrain ghost-small-v0.5 from scratch with all four switches on. Target:
   60K steps, ~4M assistant-supervised tokens / step at effective batch 32.
5. Re-run chat-tune (existing pipeline, no changes needed).
6. Re-run benchmarks for the v0.4 → v0.5 delta.

---

## What we expect to see

Honest forecast based on the cited 2024–2026 references:

- **+1.5 to +2.5 nat improvement** on val_loss vs v0.4 ghost-small at the
  same step count (RoPE + SwiGLU together account for most of this).
- **20–30% faster wall-clock per step** (RMSNorm savings + SwiGLU compute
  overlap).
- **~20% lower token count for the same corpus** (custom BPE) → more epochs
  per training run at the same compute.
- **Length extrapolation** to ~2048 ctx without retraining (RoPE), useful for
  the RAG layer landing in parallel.

If we observe less than +0.8 nat improvement at v0.5 step 30K vs v0.4 step
30K, that's a signal that the tokenizer change is hurting more than the
architecture change is helping — investigate before committing further compute.
