# Distillation pipeline (ghost-3B+ corpus expansion)

The corpus problem at ghost-3B+ is documented in
[`hardware_pathway.md`](hardware_pathway.md): Chinchilla-optimal
training of a 3B model wants 60B tokens, the current GhostLM corpus
is 363M, and the remaining cybersec text on the public web is
mostly tapped out. The lever past ghost-3B is **synthetic data
generated by a strong teacher model from existing GhostLM corpus
seeds.** This doc describes how that pipeline is built.

## What gets distilled (four content types)

Each type targets a kind of cybersec writing the current corpus is
either thin on or completely missing. Synthesis fills in the gap
with teacher-grade prose that conditions on real seed records from
the existing corpus, so the synthetic data inherits factual
grounding rather than confabulating freely.

| Type | Seeds | What the teacher generates | Target volume (ghost-3B) |
|---|---|---|---:|
| CTF walkthroughs | MITRE ATT&CK, CAPEC | 5-15 step end-to-end CTF write-ups demonstrating a technique against a fictional target, with mitigation paragraph | 50K records |
| Threat modeling | OWASP Top 10, CWE | STRIDE-style threat models for component diagrams: assets, threats, mitigations, residual risk | 30K records |
| Deobfuscation | exploitdb POCs, security_code | Step-by-step deobfuscation walkthroughs of obfuscated PowerShell / JS / shellcode, naming each transform | 20K records |
| Malware analysis | MITRE ATT&CK, CISA KEV | Forensic-style analysis prose: triage, static analysis, dynamic analysis, IoC extraction, attribution caveats | 30K records |

Total: 130K distilled records at ~500 tokens each ≈ **65M synthetic
tokens**. Mixed in at 5x oversample weight against the existing
363M-token corpus, that produces an effective ~688M-token blend (one
epoch). Three epochs of that hits ~2B tokens seen, enough to make a
ghost-3B run informative even though it's still sub-Chinchilla.

The volume target is conservative; the real ceiling is teacher cost
(see budget table below). Bigger volumes are feasible if budget grows.

## Provider abstraction

[`scripts/distill_common.py`](../scripts/distill_common.py) gives one
uniform `call_provider` interface. Every per-type distill script
imports from it and selects a provider by config. The four supported
backends:

| Backend | Use when | Budget | Throughput |
|---|---|---:|---:|
| Ollama (local) | Smoke testing, free-tier scaling | $0 | M4: ~30 s/record on qwen2.5:14b |
| Anthropic API | Best generation quality, security-aware | $0.005-0.015/record (Sonnet) | ~5 s/record |
| OpenAI-compatible | Cost-efficient via Together / Groq | $0.003-0.01/record on Llama-3.3-70B at Together | ~3 s/record |

Per-type cost scales with target volume. Rough budget envelopes for
the full ghost-3B target volume above (130K records):

| Provider | Cost (130K records) | Wall-clock |
|---|---:|---:|
| Ollama (free, local M4) | $0 | ~45 days continuous |
| Together meta-llama-3.3-70b | ~$400-800 | ~5 days |
| Anthropic claude-sonnet-4-6 | ~$1,300-2,000 | ~7 days |
| Anthropic claude-opus-4-7 | ~$8,000-12,000 | ~10 days |

Recommended path: **Ollama for the first 10K records (smoke test,
prove the pipeline works, calibrate quality filters)**, then
**Together Llama-3.3-70B for the production volume** (best
$/record-quality at 2026 prices), with **Sonnet for a final 10%
quality top-tier** on the highest-impact seeds (rare techniques,
CISA-listed exploited CVEs, OWASP Top 10).

## Resume safety + dedup

Distill runs are designed to be resumable across thousands of
records. Every per-type script:

- Writes one record at a time to its output JSONL with explicit
  flush, so a kill loses at most one record.
- Indexes already-completed seeds via `ResumeIndex` (reads the
  output file at startup). Re-running with the same args picks up
  where the previous run stopped.
- Drops near-duplicate generations via `content_dedup` (5-shingle
  Jaccard >= 0.9). Catches the failure mode where a teacher model
  generates identical walkthroughs for related-but-distinct seed
  records.

A single distill job can run for days; the pipeline assumes that's
the normal case, not an exception.

## Quality filters

`distill_common.quality_ok` rejects:

- Length out of band (< 80 words or > 1500 words).
- Refusal markers ("I can't help with", "as an AI", etc.).
- Runaway repetition (any 8-word phrase appearing 5+ times in the
  output).

Per-type scripts can layer additional filters on top. CTF
walkthroughs require step numbering (`^[0-9]+\.` lines); threat
models require the four STRIDE categories appear at least once;
deobfuscation walkthroughs require the input obfuscated source AND
the deobfuscated output both be present in the response.

## Output schema

Every distilled record uses the `DistillRecord` dataclass:

```json
{
  "id":           "distill_ctf#T1059#a3f2c1d8e9",
  "source":       "distill_ctf",
  "teacher":      "anthropic/claude-sonnet-4-6",
  "seed_source":  "mitre_attack",
  "seed_id":      "T1059",
  "text":         "<the generated walkthrough body>"
}
```

`source` is the field source mixers read at training time; setting
`distill_ctf` (etc) lets us oversample these records relative to
e.g. PRIMUS-FineWeb at training time without writing to a separate
corpus. `seed_source` and `seed_id` give traceability back to the
GhostLM corpus record that triggered the generation.

## When this runs

**Not now, before ghost-base.** The ghost-base v1.0 run is gated on
the existing 363M-token corpus and the rented-GPU spend. Distillation
is a separate phase, gated on:

1. The ghost-base v1.0 acceptance gate clearing (≥40% CTIBench OR
   ≥65% CTF eval OR ≥30% fact-recall). If ghost-base fails, the
   parameter-count diagnosis is wrong and adding more synthetic data
   doesn't help.
2. Ghost-3B planning kicking off (corpus growth becomes the binding
   constraint at 3B per
   [`hardware_pathway.md`](hardware_pathway.md)).
3. Distillation budget approval (~$1-15K depending on provider mix).

The pipeline scaffold lands now so it's ready when those gates
clear. Smoke-testing the pipeline on Ollama at 100-record scale is
free and worth doing this quarter to shake out bugs.

## Smoke test recipe

```bash
# Local Ollama, free, ~50 minutes for 100 walkthroughs.
PYTHONPATH=. python3 scripts/distill_ctf_walkthroughs.py \
    --provider ollama --model qwen2.5:14b \
    --max-records 100

# Inspect quality:
head -3 data/raw/distill_ctf.jsonl | jq -r .text | head -50

# Compare against existing ctftime.jsonl real walkthroughs:
head -3 data/raw/ctftime.jsonl | jq -r .text | head -50
```

If the synthetic walkthroughs read like real CTF write-ups (proper
tooling specifics, sane mitigation paragraphs, no refusal text),
the pipeline's working. Move to paid-provider production volume.
