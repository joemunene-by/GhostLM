# v0.9 qualitative compare: ground-truth read of the cross-bench finding

The v0.9.1 CHANGELOG and release notes lean on a 9-point lead on the
in-repo CTF MCQ eval to argue that the corpus-density swing (PRIMUS +
CWE + OWASP + RFCs at 273M tokens) actually moved capability, even
though CTIBench regressed 28.9% vs v0.7's 32.2%. **Cross-bench numbers
need a qualitative ground-truth.** This doc captures it.

`scripts/compare_chat_completions.py` runs a fixed set of 5 fact-recall
prompts through v0.4 chat-v3, v0.7 chat (the bench-winning checkpoint
of the ghost-small line on CTIBench), and v0.9 chat. Both samples
below use the same prompts and the same chat-format wrapper.

## Sampling: temperature 0.7, top_k 40 (default)

The "default" sampling settings the chat surface uses. JSON dumped to
`logs/qualitative_compare.json`.

### Prompt 1: "What is the CVE identifier for EternalBlue?" (gold: CVE-2017-0144)

- **v0.4 chat-v3:** Goes off into a heap-UAF binary-exploitation
  tangent. Doesn't engage with the question.
- **v0.7 chat:** Goes off into an HTTP / `jdb` / format-string
  vulnerability tangent. Doesn't engage with the question.
- **v0.9 chat:** "A vulnerability, which was classified as critical,
  has been found in PHPGurukul Online Online Online Online Online…"
  Hallucinates a CVE about PHPGurukul, then degenerates into a loop
  on "Online".

**Score:** 0/3 correct.

### Prompt 2: "Which CWE category covers SQL injection vulnerabilities?" (gold: CWE-89)

- **v0.4 chat-v3:** "CAPEC-94 — CWE-707." Wrong both numbers
  (CAPEC-66 and CWE-89 are correct) but at least cites the framework.
- **v0.7 chat:** Goes off into a web-application analysis tangent.
- **v0.9 chat:** "CAPEC-43 — SQL Injection." Wrong CAPEC number, but
  follows up with explanatory text about SQL injection, then
  degenerates into "CAPEC-43 — SQL Injection. CAPEC-43 — SQL
  Injection. CAPEC-42 — SQL Injection." loop.

**Score:** 0/3 correct on the CWE number; 1/3 (v0.4) at least
mentions a CWE number.

### Prompt 3: "What MITRE ATT&CK technique describes credential dumping via LSASS?" (gold: T1003.001)

- **v0.4 chat-v3:** Juicy-Potato / SeImpersonatePrivilege tangent.
- **v0.7 chat:** "CAPEC-150 — Domain name." Wrong framework
  (MITRE ATT&CK uses T-prefix, not CAPEC), then macOS Catalina
  tangent.
- **v0.9 chat:** "T1210 — Credential Disclosure. Tactic:
  privilege-escalation. Adversaries may abuse credential theft
  and other techniques…" Wrong technique number (T1210 is
  Exploitation of Remote Services; T1003 is Credential Dumping)
  but **correct format and correct framework**.

**Score:** 0/3 correct technique. v0.9 is the only one in the right
framework + format.

### Prompt 4: "What does TLS 1.3 ChaCha20-Poly1305 provide that AES-GCM does not?" (gold: better software performance without AES-NI; constant-time guarantee)

- **v0.4 chat-v3:** AES-ECB padding-oracle tangent.
- **v0.7 chat:** "T1570 — AES-GCM-SHA256-256 with an RSA public
  key." Mixes MITRE technique-numbering with cipher suite naming.
- **v0.9 chat:** Goes off into a `SOCKS Online Online…` SQL-injection
  hallucination loop.

**Score:** 0/3.

### Prompt 5: "How does SameSite=Strict on a session cookie defeat CSRF attacks?"

- **v0.4 chat-v3:** "CSRF (Server-Side Request Forgery)" — wrong
  acronym expansion (CSRF = Cross-Site Request Forgery), then Burp
  Suite tangent.
- **v0.7 chat:** Session-ID enumeration tangent.
- **v0.9 chat:** Talks about XSS via a "Rece" field; doesn't
  address SameSite at all.

**Score:** 0/3.

## Sampling: temperature 0.1, top_k 1 (near-greedy)

The fairest test of fact recall: minimize sampling noise, see what
the model "wants to say." JSON at
`logs/qualitative_compare_greedy.json`.

### Prompt 2 again: "Which CWE category covers SQL injection?"

- **v0.4 chat-v3:** SQL injection CTF tangent.
- **v0.7 chat:** Hallucinates "code-projects Simple Online Booking
  System 1.0" CVE.
- **v0.9 chat:** **"CAPEC-89 — SQL injection."** Wrong framework
  (CAPEC vs CWE), but **the number 89 is exactly the correct CWE
  identifier**. The model has the right magic number near the
  surface for "SQL injection," and it confused which framework
  attaches to that number. Then degenerates into a loop.

This is the honest read of the v0.9 cross-bench finding: **v0.9 has
factual numbers and identifiers closer to the surface than v0.4 or
v0.7**, but it can't yet wire them up to the right framework or
question. It's a meaningful capability gain that doesn't yet show
in clean qualitative output.

### Prompt 3 again: "MITRE technique for LSASS dumping?"

- **v0.4 chat-v3:** Compromised-network tangent.
- **v0.7 chat:** "T1559 — the target system…" (T1559 is
  Inter-Process Communication, not credential dumping). Correct
  framework + format, wrong technique.
- **v0.9 chat:** "T1559.001 — credential extraction. Tactic:
  defense-evasion." Wrong technique number (T1559.001 is Component
  Object Model; T1003.001 is correct for LSASS), wrong tactic
  (T1003 is credential-access, not defense-evasion), but **correct
  format with sub-technique notation, the topic word
  "credential extraction" is right, and the structure mirrors a
  real MITRE entry**.

v0.9 is closer to the right answer than v0.7 is, even though both
miss. The gap is real but small.

## Honest summary

1. **v0.9 IS qualitatively the most-fact-aware chat-tune in the
   ghost-small line.** On greedy decode, it lands on the right
   magic numbers ("89" for SQLi CWE) and the right format (T-prefix
   sub-techniques like "T1559.001" with tactic and citation
   structure). v0.4 and v0.7 don't even surface the right frameworks.

2. **None of the three models reliably answers a fact-recall
   question.** The 50%+ on the in-repo CTF MCQ eval is real signal
   from text-scoring's preference for option-strings over
   distractors, not from the model "knowing" the answer in any
   actionable sense. A 4-way MCQ where the right option text is
   topically distinguishable from the wrong options can be solved
   by texture matching alone.

3. **v0.9 has new repetition pathology.** "Online Online Online…",
   "SSL-enabled SSL-enabled…", "CAPEC-43 — SQL Injection. CAPEC-43
   — SQL Injection." loops appear on greedy decode and even
   surface at temperature 0.7. This is new vs v0.4 and v0.7. Most
   likely cause: PRIMUS-FineWeb crawl text has high local
   repetition (SEO-spammy listing pages, navigation chrome) that
   pushed v0.9's attention into self-reinforcing patterns. Worth
   documenting as a known regression in the qualitative direction
   even as the bench numbers move favorably.

4. **All three models default to "explain a CTF challenge"
   completions on neutral fact prompts.** Reflects the SFT data
   composition: most chat training comes from CTF writeups, MCQ
   examples, and instruction-style cybersec text. The model
   absorbed "this is what you say in this domain" not "this is how
   you answer a question." A more direct factual SFT pass (Q→A
   pairs without writeup framing) would help.

## Implications for ghost-base

The cross-bench finding stands but is more nuanced than "v0.9 is
smarter." Specifically:

- **The bench measures register matching + topical distinctness,
  not factual recall.** A larger bench with adversarial distractors
  that share register but differ on facts (e.g., wrong-but-plausible
  CVE IDs as distractors against the right one) would expose the
  gap that text-scoring currently hides.
- **v0.9's qualitative wins (right magic numbers, right framework
  formats) compound with parameter count if ghost-base learns to
  bind them correctly.** SmolLM2-360M and Phi-3.5-mini show
  factual binding emerging in the 300M+ range. Ghost-base's
  acceptance gate should measure factual binding directly via a
  free-form fact-recall benchmark with rubric grading by Qwen-14B,
  not just MCQ accuracy.
- **The repetition pathology in v0.9 is a warning sign.** If
  ghost-base inherits it, the model will be unusable for
  free-form generation regardless of MCQ scores. Mitigations:
  filter PRIMUS-FineWeb shards by repetition density, add a
  repetition-penalty loss term, or post-train with anti-repetition
  rewards.
